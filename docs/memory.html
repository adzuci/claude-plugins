Memory as reliability practice

A Karpathy-style LLM wiki lets me ask questions about my past AI sessions: what I keep redoing, and whether the time and tokens paid off.

First useQuery past sessions
FoundationGit-backed Markdown
CaptureHooks and importers

A good AI session should leave a record I can use later.

This post covers three things: what the wiki is good for, how the capture hooks work, and one way to set it up. A few days of session recaps is enough to start asking questions across your work history. Underneath, it is a small collection of Markdown files with an index.

The first question worth asking it: what does my own work history say I should improve?

Question your own work history

With recaps on disk, I can ask things I cannot answer from memory or from one transcript. Where am I repeating the same manual work? Which tools keep helping? What did I leave half-finished? Which expensive sessions ended in something shipped, time saved, or a risk removed?

The answers are imperfect, but they come from work I did, which makes them more useful than general productivity advice.

How capture works

Obsidian only displays the Markdown. Capture happens in each AI client, and every path ends in the same daily note.

Claude Code SessionEnd hook → archive + summarize → Daily Markdown note
Codex local rollout files → idempotent importer → Same daily note
Antigravity SessionEnd or importer → compatible entry → Same daily note

1 · Capture locally

Write the facts first

Claude archives the JSONL transcript under ~/.claude/transcripts, then appends the time, project, session ID, transcript path, and locally calculated token totals to sessions/YYYY-MM-DD.md.

2 · Summarize cheaply

Then a short summary

For a substantive session, a detached Haiku call reads only the last 20 KB of user and assistant prose, not tool results or hidden reasoning, and appends at most eight bullets under Did, Decisions, Blockers, and Next.

3 · Recall on demand

Read only what is relevant

A managed instruction block points future Claude sessions to the vault index. The assistant reads only the notes relevant to the current task; raw transcripts stay outside the default context path.

Guardrails: trivial sessions skip the model call; summarization runs with MCP disabled and a ten-cent ceiling; a recursion flag stops the summarizer from logging itself. Codex uses a pull importer when no true session-end hook is available and tracks imported IDs so retries do not duplicate entries.

Why I trust it

It is built the way I want any infrastructure built: local, readable, reversible, and explicit about what it writes. The setup skill runs read-only preflight checks, asks before touching dotfiles, backs up settings, and leaves the hook as a normal shell script you can read or remove.

All of this ships as the public memory plugin. /memory:memory-setup scaffolds the vault, installs the useful Obsidian pieces, wires Claude session capture, and offers compatible Codex and Antigravity importers. Optional sync keeps the vault converged across machines; optional git-crypt encryption keeps sensitive directories readable locally while the remote sees ciphertext.

The folder names are incidental. The pattern is: capture everything, start each session from a small index, keep raw transcripts out of the default context, and promote only durable facts, decisions, references and preferences.

What more history gives you

After a few days, a one-off retrospective can find recurring friction and missed follow-ups. With more history, scheduled reports can compare cost with outcomes, daily wrap-ups can recover half-finished work, and a few non-proprietary lessons can become posts like this one. Most of what is captured should never leave the vault.

How to tell it is working: new sessions need less preamble, and you stop searching for where a decision was made.

Install the plugin

Add the marketplace, install memory, and run setup. The skill previews its writes and asks for confirmation.

Codex

codex plugin marketplace add adzuci/claude-plugins
codex plugin add memory@adzuci-plugins
/memory:memory-setup

Claude Code

claude plugin marketplace add adzuci/claude-plugins
claude plugin install memory@adzuci-plugins
/memory:memory-setup

During setup: When the skill asks you to run gh auth login, type ! gh auth login directly into the Claude Code prompt. The ! prefix runs it in your terminal so the browser flow works correctly.

Tested on macOS. The skill installs Obsidian, the GitHub CLI, and jq automatically if missing. Linux and Windows compatibility PRs are welcome.

Prerequisites and setup notes

Claude Code requires Node.js 18 or newer. GitHub CLI is needed only when the skill creates the private vault repository for you; on macOS, Homebrew is the fallback installer for missing tools.

npm install -g @anthropic-ai/claude-code
brew install gh
gh auth login

In Claude Code, /auto reduces installation prompts. When setup asks for GitHub authentication, run ! gh auth login so the browser flow opens from your terminal.
