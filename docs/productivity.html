An operating loop for AI-assisted work

The memory vault answers "what did we decide?" This plugin answers the next question: "what should I do with that, today and this week?"

Part two of a series — start with Memory as reliability practice.

A memory layer on its own is a filing cabinet. It becomes an operating system when there are small, boring loops that move work through it.

After I set up the memory vault, the failure mode changed. I stopped losing decisions, and started losing follow-ups: a task mentioned mid-session that never landed anywhere, a session cleared with uncommitted work still sitting in the tree, a Friday where I could not say what the week's AI-assisted work actually taught me.

The productivity plugin is my answer: a handful of skills that share one vault and one convention, each small enough to read in a few minutes.

Capture is cheap. What is expensive is re-finding the task, the loose end, or the pattern three weeks later.

The loop

The skills form a daily-to-weekly cadence. Each one works standalone, but they compound:

In the moment

  • /productivity:todo — capture a durable task in the vault's Kanban backlog.md. Idempotent: re-adding an item deduplicates, and an explicit "urgent" promotes it instead of duplicating it.
  • /productivity:wrapup — before /clear, check for uncommitted changes, unpushed commits, running jobs, and open obligations. It tells you whether it is actually safe to clear.

Daily and weekly

  • /productivity:daily-wrapup — end-of-day review: yesterday's goals, today's outcomes, tomorrow's preview, and a goal commit into the vault session note.
  • /productivity:ai-coach — a Friday, report-only review of the week's curated session notes: repeated friction, capabilities I keep bypassing, and memory candidates. It writes a report; it changes nothing.

/productivity:productivity-setup ties it together: it installs managed local copies of these skills for every Claude Code and Codex client it detects, records your vault path in ~/.config/adzuci-productivity/config.json, and offers to schedule the Friday coach with whatever scheduler is native to the client you are in. The plugin also ships /productivity:budgetclaw-setup for local spend monitoring and an agent-ops pair for privacy-safe scheduled agents.

Design guardrails

The same rules as the memory plugin, because they are the reason I trust it:

Everything is plain files. Tasks are Markdown checkboxes in a Kanban board Obsidian can render; coach reports are dated Markdown in coaching/. Installs are dry-run first and confirmation-gated, they never overwrite an unmanaged skill with the same name, and every managed copy carries a marker file so updates are safe and removal is obvious. The AI coach is deliberately report-only: it requires evidence from multiple sessions before recommending anything, verifies invocations against skills you actually have installed, and never writes to durable memory without approval.

Honest limitations

It assumes the vault convention from the memory plugin — a sessions/ directory of curated notes is what makes the coach useful; without it, weekly mode has little to read. The Kanban layout is an opinion (six fixed sections) rather than a framework. Scheduling is best-supported on the clients I use daily; elsewhere the setup skill hands you the exact manual command instead of installing cron jobs behind your back. And like everything in this repo, it is tested primarily on macOS.

The practical test: if this is working, tasks stop living in chat scrollback, sessions end clean, and Friday's coach report occasionally tells you something about your own habits you did not notice.

Install the plugin

Add the public marketplace once, install, then run setup.

Claude Code

claude plugin marketplace add adzuci/claude-plugins
claude plugin install productivity@adzuci-plugins
/productivity:productivity-setup

Codex

codex plugin marketplace add adzuci/claude-plugins
codex plugin add productivity@adzuci-plugins
/productivity-setup

Setup asks before it writes anything outside the current project. Pairs best with the memory plugin's vault, but any Obsidian vault works.
