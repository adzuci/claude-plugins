An operating loop for AI-assisted work

AI makes it cheap to start work. The hard part is carrying it across sessions without dropping commitments or rebuilding context. These five skills do the carrying, and each is short enough to read.

Part two of a series. Start with Memory as reliability practice, then Reflecting your own work back as a learning plan.

Why I built this

What runs short in AI-assisted work is continuity: knowing what matters, what changed, and what happens next.

LLMs let me explore more ideas and build faster. They also give work more places to get lost. A task comes up mid-session and never reaches the backlog. A session gets cleared with uncommitted work in the tree. Friday arrives and I have to reconstruct what the week's AI work produced. Each session got faster; the gaps between sessions became the bottleneck.

My memory vault stopped me losing decisions, but it did not make me follow through. I needed four things: commitments land in one backlog, sessions end with recoverable work, daily status comes from the source systems, and repeated friction shows up at the end of the week.

The plugin does not automate my job. It handles capture and reconstruction, so my attention goes to judgment and to people.

The approach comes from reliability work: when a manual step keeps failing, build a small system with a clear contract. Here that is the productivity plugin: five skills that share one vault and one convention, each short enough to read in a few minutes.

AI makes work cheaper to start. The loop makes it more likely to get finished.

The loop

The skills run on a daily and weekly rhythm around one git-backed vault. The vault is the only shared state: every skill reads from it and writes plain Markdown back, so each works on its own.

Two skills run in the moment, three on a daily-to-weekly rhythm:

In the moment

  • /todo: capture a durable task in the vault's Kanban backlog.md. Re-adding an item deduplicates instead of stacking, and "urgent" promotes the existing item instead of creating a second copy.
  • /wrapup: the check before /clear. It looks for uncommitted changes, unpushed commits, running jobs and open obligations, and tells you whether the session is safe to clear.

Daily and weekly

  • /standup: a daily or weekly status built from Jira, the backlog, and daily reports. The paste-ready block is capped at 90 words and eight bullets; private notes list the tickets you could close in five minutes.
  • /daily-wrapup, end-of-day review: yesterday's goals, today's outcomes, tomorrow's preview, and a goal commit written back into the vault's session note.
  • /ai-coach: a Friday, report-only review of the week's session notes: repeated friction, capabilities I keep bypassing, and memory candidates. It writes a report and changes nothing.

/productivity-setup installs managed local copies of these skills for every Claude Code and Codex client it detects, records your vault path in ~/.config/adzuci-productivity/config.json, and offers to schedule the Friday coach with whatever scheduler is native to the client you are in. The plugin also ships /budgetclaw-setup for local spend monitoring and an agent-ops pair for privacy-safe scheduled agents.

Each skill has a contract

I let these run unattended because each has an explicit, testable contract. Three examples:

SkillThe contractWhy it holds
/todo Adding the same task twice is a no-op; "urgent" promotes rather than duplicates. A Python helper normalizes bullets, deduplicates case-insensitively, and writes atomically; behavior is pinned by unit tests, not by prompt wording.
/standup The paste-ready block is always under 90 words and eight bullets. A checker script runs against the draft before it is returned; boundary cases (exactly 90 words, exactly eight bullets) are covered in the test suite.
/ai-coach Report-only: it never writes durable memory or mutates a ticket on its own. It requires evidence from multiple sessions before recommending anything, verifies invocations against skills you have installed, and stops at proposing.

Design guardrails

The same rules as the memory plugin:

Everything is plain files. Tasks are Markdown checkboxes in a Kanban board Obsidian renders natively; coach reports are dated Markdown in coaching/. Installs do a dry run first and ask for confirmation. They never overwrite an unmanaged skill of the same name, and every managed copy carries a marker file so updates are safe and removal is obvious. Scheduling uses the client's own scheduler; where there is no good native option, the setup skill hands you the exact manual command instead of writing a cron job. Writes that could compound (task capture, goal commits) are idempotent, so a double-run or a retry never corrupts the board.

What changed in practice

After four months, counted from the vault it writes to:

610
session summaries archived since Mar 16
84
daily notes the loop reads and writes
19
days I closed out with /daily-wrapup

The SessionEnd hook does the archiving, so the 610 summaries took no effort and I stopped deciding what was worth writing down. I ran /daily-wrapup on 19 days, and each of those next mornings started from a written plan. Tasks moved from chat scrollback into the backlog, because capturing one is quicker than scrolling to find it. Some Fridays the coach names a habit I had not noticed.

How to tell it is working: tasks stop living in chat scrollback, sessions end clean, and some Fridays the coach report shows a pattern you had missed.

Why I am publishing it

I want to compare failure modes and contracts with other people building AI-assisted workflows. The implementation is public so you can test it and show me better loops: open an issue or reach out. If this is how you like to work, see Apollo's open roles.

Limitations

It assumes the memory plugin's vault layout. The coach reads the notes in sessions/; without them, weekly mode has little to go on. The Kanban layout is fixed at six sections. Scheduling works best on the clients I use daily; elsewhere you get the manual command. Like everything in this repo, it is tested mainly on macOS; Linux and Windows reports are welcome.

Install the plugin

Add the public marketplace once, install, then run setup.

Claude Code

claude plugin marketplace add adzuci/claude-plugins
claude plugin install productivity@adzuci-plugins
/productivity:productivity-setup

Codex

codex plugin marketplace add adzuci/claude-plugins
codex plugin add productivity@adzuci-plugins
/productivity-setup

Setup asks before it writes anything outside the current project. Pairs best with the memory plugin's vault, but any Obsidian vault works.
