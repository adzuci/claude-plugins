# Team Attribution on GKE

Background for SKILL.md Step 2d. Everything here was verified read-only on 2026-09-14 against
`apolloio/leadgenie` and `apolloio/devops`; re-check paths before quoting them in a report.

## Why the billing export cannot split GKE by team today

- Sidekiq runs as **one Deployment per worker** (`sidekiq-<name>`, 763 in production) in the
  `leadgenie` namespace, defined in `kubernetes/production/sidekiq-workers/values.yaml`. About 700
  are `preemptive: true` and land on the shared `spot-v4` / `spot-v5` node pools; the rest share
  `main-v4` / `main-v5` with the Rails web tier (`devops/terraform/gcp/prod/gke-cluster-prod.tf`).
- Node pools carry only `infra_workload=gke` and `infra_cluster=production`. Nothing team-specific
  reaches the billing export, so Q12 shows a single `gke / production` line.
- Pod labels only reach the export through **GKE cost allocation**
  (`costManagementConfig.enabled` on the cluster), which adds `k8s-namespace` and `k8s-label/<key>`
  labels to GKE compute rows from the day it is enabled. It is **not enabled on production** as of
  2026-09-14. Tracking: INFRA-2186; devops PRs #4071 (module toggle) and #4072 (staging + ops first).

## What already exists, so do not rebuild it

| Piece | Where | State |
| --- | --- | --- |
| Queue → team mapping | `leadgenie/kubernetes/charts/sidekiq-workers/cluster-owners.yaml` | Generated by the `file-ownership-check` workflow from `apollo-dev-teams.yml` + `CODEOWNERS`. 723 entries, 17 teams. Do not edit by hand. |
| Runtime lookup | `packs/sidekiq/app/public/sidekiq_util.rb` `apollo_team_for_queue` | Used for PagerDuty routing, the `apollo_team` OTel span attribute, and Prometheus gauges with a `queue_owner` label. |
| Pod label | `kubernetes/charts/sidekiq-workers/templates/deployment.yaml` | Stamps `app.kubernetes.io/area: <team>` on every Deployment and pod template; defaults to `be-platform`. |
| Coverage | computed from `values.yaml` | 719 of 763 workers resolve to a team; 44 default to `be-platform` (shared / dynamic queues). leadgenie PR #103310 addresses most of them. |
| kube-state-metrics | Alloy config in `devops` | Does **not** export `app.kubernetes.io/area` (`label_app_kubernetes_io_area` is empty), so Grafana cannot group by team yet. |

Top owners by worker count: native-data 230, customer-data-platform 121, rep-experience-be 82,
warm-outbound 73, deliverability 50.

## Interim directional number (before cost allocation)

OpenCost metrics exist in Grafana Cloud Prometheus for production pods:
`container_cpu_allocation` and `container_memory_allocation_bytes`. Sum per `sidekiq-*` pod, join
offline to `cluster-owners.yaml` by worker name, and weight against the `gke/production` net figure
from Q12. Label any number produced this way **list-price, pre-CUD, requests-based, directional
only**. Do not put it in a KPI tile.

## Path to a real split, ranked by effort

1. **Small, devops:** add `app.kubernetes.io/area` to the kube-state-metrics
   `--metric-labels-allowlist` so `sum by (label_app_kubernetes_io_area)` works live in Grafana.
1. **Small, leadgenie:** close the 44 `be-platform` defaults and alert when `apollo_team_for_queue`
   returns nil.
1. **Medium, devops:** enable GKE cost allocation on production (INFRA-2186). Then Q14 in
   `bq-queries.md` splits GKE net by `k8s-label/app.kubernetes.io/area` with CUD credits applied.
   Collection starts on enablement day; the first clean month-over-month comparison is two months
   later.
