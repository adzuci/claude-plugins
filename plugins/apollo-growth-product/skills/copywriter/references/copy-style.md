# Apollo Copy Style Guide

Shared style rules that apply across **all** feature gate surfaces. These are non-negotiable — every draft must pass all of these checks.

## Capitalization

- **Sentence case everywhere** — headers, descriptions, buttons, bullets
- Proper nouns and product names are capitalized (e.g., "Apollo," "Professional plan")
- Plan names are capitalized when used as proper nouns (e.g., "Upgrade to Professional")
- Feature names follow product convention (check existing UI for casing)

## Punctuation

- **No period in titles or headers**
- **No exclamation marks** — ever, in any component
- Descriptions may end with a period if they are complete sentences
- Bullets do **not** end with punctuation
- Use commas and em dashes sparingly; prefer short sentences over complex punctuation

## Voice and Tone

- **Active voice always** — "Upgrade now to unlock..." not "Unlocking can be done by upgrading..."
- **Clarity over cleverness** — straightforward language beats wordplay
- **Plain, everyday language** — no jargon, no marketing fluff, no buzzwords
- **Confident, not pushy** — state the value clearly without overselling
- **Helpful, not condescending** — the user hit a limit; help them, don't lecture them

## Structure

- **Bold the upgrade benefit** in descriptions when a specific benefit is mentioned
  - Example: "Upgrade now to **select unlimited contacts** and build lists faster."
- **Lead with outcomes** — what the user can do, not what the feature is
  - Good: "Select unlimited contacts from any list"
  - Bad: "The unlimited selection feature allows bulk operations"
- **One idea per sentence** — keep descriptions scannable
- **One idea per bullet** — no compound benefits in a single bullet

## CTA Patterns

- Primary CTAs should use the patterns specified in the surface file
- Keep CTAs action-oriented: verb + object
  - Good: "View pricing plans," "Upgrade now," "Buy credits"
  - Bad: "Click here," "Go," "OK"
- Secondary CTAs are **reserved for "Talk to Sales"** — only for core teams, coordinate with Conversion and Sales teams first
- When legal risk requires informational CTAs, use: "Continue," "Next," "Learn more"

## Character Counting

- Count every visible character including spaces
- Do NOT count quotation marks unless they appear in the final copy
- Trim leading/trailing whitespace before counting
- If a draft exceeds the limit by even 1 character, it must be revised

## Do's and Don'ts

**Do:**

- Write copy that a first-time user would understand
- Match the tone specified in the surface file
- Test copy at the character limit — does it still read well at max length?
- Consider the user's emotional state (they just hit a limit or got blocked)

**Don't:**

- Use "unlock" as a verb more than once per surface
- Start every header with "You've" — vary the patterns
- Use technical plan IDs or internal terminology
- Reference competitors or comparison language
- Promise specific outcomes without PMM confirmation (e.g., "30% more meetings")
