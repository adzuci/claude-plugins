# Persuasion Rules

Eleven principles for higher-converting in-product copy. **ON by default** — skip with "Be plainspoken" in arguments.

*The animating question behind every rule: **"Why should I care, right now?"***

______________________________________________________________________

## The Rules

### 1. Three-Question Test

**Rule:** Every header and description must pass all three questions: Can I visualize it? Can I falsify it? Can nobody else say this?

**Example:**

- Fail: "Unlock powerful prospecting tools" (abstract, unfalsifiable, any CRM could say it)
- Pass: "Find 10x more verified emails in one search" (visual, measurable, specific to Apollo's data)

### 2. Concrete over Abstract

**Rule:** Replace abstract benefits with specific, visual objects you could "drop on your foot."

**Example:**

- Abstract: "Enhance your outreach capabilities"
- Concrete: "Send 500 personalized emails before lunch"

### 3. The 1-Mississippi Test

**Rule:** Copy must land in two seconds or less. If a reader can't get it at a glance, simplify.

**Example:**

- Slow: "You've utilized all of the available contact export credits allocated to your current subscription tier"
- Fast: "You're out of export credits"

### 4. Point, Don't Talk

**Rule:** Swap adjectives for evidence. Don't say what you are — show what you do.

**Example:**

- Talking: "Our powerful engagement suite"
- Pointing: "Sequences that book 3x more meetings"

### 5. Falsifiable Claims

**Rule:** Make specific, provable statements. Vague praise is invisible; precise claims stick.

**Example:**

- Vague: "Better data quality"
- Falsifiable: "95% email accuracy, verified in real time"

### 6. Nobody Else Can Say This

**Rule:** If you swap your product name for a competitor's and the copy still works, it's too generic. Rewrite until only you can claim it.

**Example:**

- Generic: "Grow your pipeline faster" (any sales tool could say this)
- Only Apollo: "275M+ contacts, updated weekly — search them all"

### 7. Kaplan's Law

**Rule:** Any word not working for you is working against you. If you can remove a word without losing meaning, remove it. This applies to ideas too — if two sentences say the same thing across a header and description, cut one.

**Example:**

- Before: "In order to be able to access these additional features"
- After: "To access these features"

### 8. Conflict Creates Interest

**Rule:** Frame value through contrast — before vs. after, hard way vs. easy way, problem vs. solution.

**Example:**

- Flat: "Automate your outreach"
- Contrast: "Stop writing one email at a time. Send 500 at once."

### 9. Reader First

**Rule:** Write from the reader's self-interest, not the product's capabilities. Ask "what does the reader gain?" — if the benefit isn't obvious in one reading, rewrite.

**Example:**

- Product-out: "Sequences is now available on your plan"
- Reader-in: "You can now automate follow-ups and book more meetings"

### 10. Reassure

**Rule:** People hesitate when they doubt. Add a short safety net near friction points — a commitment-reducing phrase removes hesitation before it forms.

**Example:**

- Without: "Set up your sequence"
- With: "Set up your sequence — takes 2 minutes, no prep needed"

### 11. Sound Human

**Rule:** Read the copy aloud. If it sounds like a press release or ToS clause, rewrite until it sounds like something you'd say to a friend.

**Example:**

- Corporate: "Your current subscription tier does not include access to this functionality"
- Human: "This feature isn't included in your plan"

## How to Apply

After drafting each component, run this self-check:

1. **Three-Question Test** the header and description (visualize? falsify? only-us?)
1. **Reader First** — is the benefit to the reader obvious in one reading?
1. **Scan for abstraction** — circle any word you can't picture. Replace it.
1. **1-Mississippi** — read the header aloud. If you need a breath, trim it.
1. **Kaplan's Law sweep** — delete every word that doesn't earn its place. Cut repeated ideas across header and description too.
1. **Conflict check** — can you add a before/after or problem/solution frame?
1. **Reassure** — is there a hesitation point? Add a safety net phrase.
1. **Sound Human** — read everything aloud. If it sounds corporate, rewrite.

Revise any component that fails before presenting the draft.

## Persuasion Quality Score

Score every draft against all 11 rules:

- Each rule scores **Pass** (✓), **Partial** (△), or **Fail** (✗)
- **Score = (Pass count + 0.5 × Partial count) / 11**, displayed as `X / 11`
- A rule scores **Partial** when it could be applied better with missing context (e.g., no differentiator provided → rule 6 "Nobody Else Can Say This" is partial)
- A rule scores **Fail** when the copy violates it despite having enough context to comply
- Rules that don't apply to a component (e.g., Reassure on a header) are auto-Pass

## When Context Is Missing

- When a rule can't be fully applied due to missing user context (no differentiator, no specific numbers, etc.), **prompt the user once** for the missing info
- If the user doesn't supply it, draft the best copy possible and mark the affected rules as **Partial** in the score
- Add a **Gaps** note below the score table listing what context would improve the draft (e.g., "A specific differentiator would strengthen rules 1 and 6")

## Opting Out

If the user includes **"Be plainspoken"** (case-insensitive) in their arguments, skip these rules entirely. Use clear, direct language without persuasion techniques. Note the skip in the output.
