# HTML Report (`--html`)

Write one self-contained file, `claude-plugins-pr-triage-YYYY-MM-DD.html`, in the current
working directory unless the user gives a path, with the same content as the Markdown triage. Tell the user the path. With `--html`, print only a short chat
summary plus the file path; full tables live only in the file.
Do not publish or upload it unless the user asks.

## Requirements

- Single file: inline `<style>` and optional inline `<script>`; no external fonts,
  scripts, images, or network requests.
- Light and dark: define colors as CSS variables on `:root`, override under
  `@media (prefers-color-scheme: dark)`, and set an explicit body background.
- Layout: readable at phone width, 16px side gutters, tables scroll horizontally inside
  their own wrapper, no page-level horizontal scroll.
- Structure: title with snapshot date and open-PR count, the provenance note, one
  `<section>` per non-empty group with the same columns as the Markdown tables, then the
  numbered first-pass actions.
- Each PR cell is a real link to the PR. Escape all PR titles, bodies, and author text
  before inserting them into HTML.
- Optional: a small inline script that filters rows by text and toggles groups. The page
  must be fully readable with scripts disabled.
- Do not add an "internal only" banner unless the data warrants one; the report lists
  public-to-org PR metadata only.

## Provenance Note

Place above every group, small and muted:

> **Generated by a Claude skill and may contain errors.** Assembled from GitHub PR
> metadata, CODEOWNERS, and optional Slack threads on the snapshot date. Verify anything
> load-bearing before acting on it.

End the page with the line "No GitHub state was changed."

## Verification

The Browser pane opens `file://` pages as a static snapshot, so JS-dependent checks are
skipped. Use grep checks instead: no external URLs (`grep -E 'https?://' ` should only
match PR links), and PR titles are escaped.
