## Action Item Format Rules

Every action item MUST include the 4 required fields. Add the optional Intercom evidence field only when a relevant conversation/thread exists. No tables — use the task checkbox format above.

1. **Article** — markdown link with full `knowledge.apollo.io` URL + article ID. For `NEW_FEATURE` where no article exists, write: `**New article needed: "[Suggested Title]"**`

1. **Gap** — gap type tag + one-sentence description of the discrepancy between the code and the KB article. Be specific: name the feature, the behavior, and what's missing/wrong.

1. **Where to verify** — step-by-step navigation path in plain English describing how a PM can trigger the relevant behavior in the product. Include the direct `app.apollo.io` link. Derive links from `routes.tsx`, not from guesses.

   - Good: "Navigate to Settings → Integrations → Salesforce → Pull tab → click 'Sync History'. You'll see the new date range filter and sync metrics panel. Direct link: https://app.apollo.io/#/settings/integrations/crm/salesforce/contacts"
   - Bad: "Settings → Integrations → Salesforce"

1. **Recommendation** — specific, actionable change. Not "update the article" but "Add a new section titled 'View Sync History' after the 'Configure Pull Settings' section, covering: (1) date range filter, (2) sync metrics history, (3) duplicate record risk warning in pull filters."

1. **Relevant Intercom thread** — optional evidence link. Include this field only when the input, ticket, support context, or fetched evidence includes a relevant Intercom conversation/thread. Use the canonical `https://app.intercom.com/...` URL and a short label such as conversation ID, customer, or issue summary. Do not invent an Intercom link; omit the field when none exists.

**Engineering owner** is included only for HIGH confidence items (per Rule 6).

## Gap Types

| Gap Type | Meaning |
|---|---|
| `STALE` | KB article describes old behavior |
| `NEW_FEATURE` | Feature shipped, no KB article exists |
| `UI_CHANGED` | UI changed, KB screenshots/steps outdated |
| `STALE_REFERENCE` | Article ID in code constants points to deleted article |
| `BROKEN_PLACEHOLDER` | URL contains placeholder text instead of real article ID |
| `INVISIBLE_ARTICLE` | Article exists on site but not linked from product UI |
| `HARDCODED_URL` | `knowledge.apollo.io` URL hardcoded in code instead of using KB.\* constant |
| `MISSING_KB_ARTICLE` | TODO comment in code flagging missing KB link |
| `INFRASTRUCTURE_GAP` | Missing tooling/enforcement for KB quality |
| `NOT_IMPLEMENTED` | PRD describes feature not found in code |
| `UNDOCUMENTED_ADDITION` | Code change not in PRD |
| `BEHAVIOR_DRIFT` | Code and PRD describe feature differently |

   - Parent: Usage Tracker data source ID in [post-run-notion.md](post-run-notion.md)
   - Use run metrics as database properties
   - Use the full gap report markdown as the database row page content

   - Write run data to `.kb-cache/usage-log.jsonl`
   - Print the row values for manual paste

After delivering output → follow post-run Notion update steps (see [post-run-notion.md](post-run-notion.md)).
