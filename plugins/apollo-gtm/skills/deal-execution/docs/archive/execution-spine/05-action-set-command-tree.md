1. Purpose
This module defines the canonical Action Set — the bounded, enumerated set of 24 actions the system can take in
response to any email thread state. This is the single source of truth for:
Action IDs (stable identifiers)
Action names and descriptions
Preconditions (boolean expressions against ThreadState)
CTA specifications per action
Word count limits per action
Stage availability matrix
Priority lock interaction rules
GRRIPS arc mappings
Postconditions (state updates after execution)
Critical Principle: The system can ONLY select actions defined in this document. Action IDs referenced in Module 03
(ThreadState), Module 06 Policy Engine), and Module 07 GRRIPS must exactly match this registry.
L Action Set  Command Tree 1

Bounded Action Set Guarantee: Actions 124 are the complete set. No action outside this range is valid. If selected_action ∉
1..24, the system MUST block and escalate.
2. Scope
In Scope
All 24 actions with complete specifications
Preconditions using ThreadState fields Module 03 v1.0.1
CTA type specifications per action
GRRIPS arc mappings per action Module 07 v1.3.1
Stage availability matrix
Word count limits by action category
Postcondition state updates
Priority lock interaction rules
Intent-action affinity mappings
Out of Scope
Precondition evaluation logic  Module 06 responsibility
Action selection algorithm  Module 06 responsibility
Message generation  Module 07 responsibility
Claim validation  Module 08 responsibility
Drift detection  Module 09 responsibility
3. Definitions
Term Definition
Action ID Stable numeric identifier 124 for an action
Action Enum String identifier (e.g., ACT_003_ANSWER_EXPLICIT_QUESTION_ONLY)
Precondition Boolean expression that must evaluate to true for action to be available
CTA Call-to-action type associated with an action's S node
Stage Availability Which deal stages permit this action
Word Limit Maximum word count for message generated by this action
Postcondition State field updates applied after action execution
GRRIPS Arc Node sequence used by Module 07 to compile the message
4. Inputs
This module is a reference specification — it does not process inputs directly. It defines the action registry consumed by:
Module 06 Policy Engine): Reads preconditions, stage availability, priority lock rules
Module 07 GRRIPS Reads arc mappings, CTA specs, word limits
Module 09 Drift Monitor): Reads postconditions for state verification
